# 清理规则完整回测：反弹卖 vs 调仓日直接卖（2026-10-29）

> 结论先行：**当前 `plan` 的“跌出保留线后等反弹 MA10 卖半 / MA20 卖完”规则，在完整引擎里
> 明显更差，应该改回“调仓日无条件卖”。**
>
> 24.3 万、12 起点、2x 成本、现金 2%、趋势倾斜开：
> - **直接卖**：年化 **+7.0%**，超额 **+0.7%**，夏普 0.46，回撤 **−18.5%**，2023+ **+6.1%**，
>   换手 **14.4x**，卖出 527 笔/起点；
> - **反弹清理**：年化 **+0.6%**，超额 **−5.7%**，夏普 0.04，回撤 **−31.8%**，2023+ **−0.5%**，
>   换手 **33.0x**，卖出 928 笔/起点。
>
> 差距 **−6.4pp/年**。旧的一阶近似“+0.65%/笔”只看了“卖出的价格”，
> **漏掉了“卖一半、剩下再卖一次”把换手从 14.4x 抬到 33x 的成本**，以及等待期间的回撤。
>
> **最终口径（公平名额约束，2026-10-29 复核）：** 回测里如果让“待清理仓位仍占名额、
> 卖出前不补替代票”，rebound 为 **+2.3%/年、超额 −3.9%、回撤 −27.6%、2023+ +0.1%、换手 34.3x**，
> 与 immediate 的差距 **−4.7pp/年**。下面 §3 的 +0.6%/−5.7%/−31.8%/33.0x 是**未加该约束**的版本，
> 会高估 rebound 的换手/成本；**以本段 −4.7pp 为准**，§3 保留作对照。
>
> 是否改 `plan` 需要用户确认（会改规则指纹、重置样本外计时，且与“深套不低点割”的行为约束冲突）。

## 1. 现在 `plan` 的清理规则

- 调仓日（防御 60 日、其余 20 日）检查持仓；跌出“名额 × 缓冲”的进入存量清理；
- 不立刻卖：挂条件单，反弹到 **MA10 卖一半**、**MA20 卖完**；
- 进入清理满 **10 个交易日**仍未反弹到位 → 收盘前卖一半；
- 已进入清理的继续挂，直到成交或下次调仓日重新评估；
- 下次调仓日又回到保留线内 → 取消清理。

设计初衷是行为约束：**不在低点一次性割**，避免用户“亏的拿着、赚的小钱就卖”的反向操作。
问题是：这条规则在完整组合里到底值不值？

---

## 2. 怎么测

在 `RollingEngine` 里新增 `cleanup` 模式，默认 `immediate`（旧回测口径），研究用 `rebound`：

- `immediate`：调仓日收盘决策，次日开盘直接卖；
- `rebound`：调仓日只标记；之后每日：
  - `high ≥ MA10` → 卖一半，限价成交价取 `max(开盘, MA10)`；
  - `high ≥ MA20` → 卖完，成交价取 `max(开盘, MA20)`；
  - 进入清理满 10 个交易日仍未反弹 → 收盘价扣滑点卖一半（**只一次**），余下继续等 MA20；
  - 下次调仓日回到保留线 → 取消清理。
- 两种模式用同一个引擎、同一套选股/调仓/成本/趋势倾斜；只改退出方式。
- 无前视：`cleanup_exits` 只用当日 high/close 和过去的 MA；新增“改未来数据、过去决策不变”测试。

**与实盘的差异（必须知道）**：

- 实盘条件单可能在盘中触及均线时成交，回测用 `max(开盘, 均线)` 近似；
- 到期“收盘前卖一半”在实盘是收盘前市价，回测用收盘价扣滑点；
- 回测的“到期只卖一次”是合理读法；实盘 `apply_patience` 若每天重复显示“到期卖一半”，
  用户可能重复卖半——那会更差，不是更好；
- 回测按 2x 成本（佣金/最低佣金/印花税/过户费/滑点全部 ×2）。

## 3. 结果（12 起点，**未约束名额版本**；最终以 §0 的 −4.7pp 为准）

| 指标 | immediate（直接卖） | rebound（反弹清理） | 差 |
|---|---|---|---|
| 年化 | **+7.0%** | **+0.6%** | **−6.4pp** |
| 超额（vs 股票池） | **+0.7%** | **−5.7%** | **−6.4pp** |
| 最差起点超额 | −0.7% | −10.2% | −9.5pp |
| 夏普 | 0.46 | 0.04 | −0.42 |
| 最大回撤 | **−18.5%** | **−31.8%** | −13.3pp |
| 2023+ 超额 | **+6.1%** | **−0.5%** | −6.6pp |
| 年化换手 | 14.4x | 33.0x | +18.6x |
| 卖出笔数/起点 | 527 | 928 | +401 |

**逐起点**：immediate 年化 +5.4%~+9.1%，12 个起点全部正；rebound 年化 −4.0%~+2.6%，
最差起点超额 −10.2%。不是单一路径的偶然。

**清理成交分布（rebound，12 起点合计）**：

| 原因 | 笔数 |
|---|---|
| 清理：反弹卖半 | 5,530 |
| 清理：反弹卖完 | 5,438 |
| 清理：到期卖半 | 167 |

**读法**：绝大多数清理都是“MA10 卖半 + MA20 卖完”两笔；到期强清只占 1.5%。
也就是说，规则的主要动作不是“等不到反弹”，而是**把一次卖出拆成两次**：
- 换手从 14.4x 到 33.0x，2x 成本下多出约 5–6pp/年；
- 等待期间继续持有下跌股，回撤从 −18.5% 扩大到 −31.8%；
- 2023+ 的超额从 +6.1% 变成 −0.5%，正好打掉了股票引擎最近唯一像样的那段。

**旧的一阶近似为什么错**：它只比较“清理卖出的价格” vs “次日开盘无条件卖”，
得到 +0.65%/笔；但没有算：
1. 卖一半后剩下的一半还要再卖一次 → 交易笔数/换手翻倍；
2. 等待期间资金被占用、不能买新票；
3. 等不到反弹的股票继续下跌 → 回撤/右尾。
**单笔价格改善 ≠ 组合净收益。**

---

## 4. 结论与建议

1. **当前反弹清理规则不通过**：12 起点、2x、2023+ 全部指向“直接卖更好”，
   公平名额约束后差距 **4.7pp/年**（未约束版本 6.4pp/年）。
2. **建议改回“调仓日无条件卖”**（`cleanup="immediate"`）：
   - 在调仓日收盘决策，次日开盘卖出，不再挂 MA10/MA20 条件单；
   - 这样换手从 **34.3x 回到 14.4x**，回撤从 **−27.6% 回到 −18.5%**，2023+ 回到 +6.1%
     （未约束版本：33x、−31.8%）。
3. **如果行为上无法接受一次性卖**：
   - 可以试“调仓日卖一半、下个调仓日无条件卖余下”的折中，但它**必须单独回测**；
     旧 A 系列（A1/A1c）在 1x 下已经从 8.5% 掉到 5.7%，2x+现金 2% 也只是 −0.9pp 超额，
     不要假设折中是免费的。
4. **不要保留“每天到期卖一半”的实现**：如果实盘 `apply_patience` 每天重复提示，
   会变成几何级卖出；要么改成一次性，要么直接改回 immediate。
5. **改 `plan` 前需要用户确认**：这是交易规则变更，会改变 `rules.fingerprint`，
   并重置真样本外计时；且与“深套不低点一次性割”的行为约束冲突。证据已经很清楚，
   但最终是用户的风险偏好决定。
