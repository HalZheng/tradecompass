## 3. 怎么跟踪

### 3.1 数据

- 每份 `plan` 同时写 `.json`（schema=1），含 `rules.fingerprint`、`base_orders`、
  `steady_orders`、`holdings`、`buys`、`rebalance`。
- `track` 读取全部 `.json`，按建议日回填 T+1/T+5/T+20、条件单触发、是否执行；
  现在覆盖：
  - 个股买入；
  - 个股清理（条件单价、是否触及、是否执行）；
  - **ETF 波段清理**（159/51/52/56/58 等前缀，自动按 ETF 读行情）；
  - **底仓补仓 / 稳健加仓/减仓**（2026-10-29 新增）。
- 流水没覆盖到 T+5 时记“未知”，不猜；行情没走到 T+N 时记“—”，不拿现价冒充未来。

### 3.2 命令

```powershell
# 全部历史（含冻结前，作基线）
tradecompass track --home ..\tradecompass-private

# 只看真样本外（冻结后）
tradecompass track --home ..\tradecompass-private --since 2026-10-28
```

### 3.3 评估节奏

- **每月**：看 `track.md` 的买入 T+5/T+20 超额、清理条件单触发率、ETF/底仓执行率；
- **每季度**：累计 3 个月，算滚动超额、最大回撤、命中率、遵从率；
- **6–12 个月**：用月度超额序列做 **Deflated Sharpe / 块 bootstrap**，并和基线（同口径、
  同成本、同资金）比较；不达标就承认“没有可验证的 alpha”，不靠改规则救。

### 3.4 判定“有效”的最低门槛

1. 6–12 个月累计净超额（相对股票池/沪深300，按实际资金与 2x 成本）**不为负**；
2. 最大回撤不超过基线的 1.2 倍；
3. `track` 的执行率/遵从率可解释（低执行率不能包装成“策略有效”）；
4. 规则指纹始终未变。

任何一条不满足，结论就是“这套规则在真实未来没有验证出优势”，而不是“再调一下参数”。
